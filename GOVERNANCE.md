# Governance

The project uses a maintainer-led, evidence-driven governance model.

## Decision principles

1. Protection security and transparent limitations come before visual novelty.
2. Deterministic and explainable behaviour is preferred over opaque scoring.
3. Hard data-validity failures cannot be overridden by an averaged confidence score.
4. Changes to protection logic require tests and documented assumptions.
5. Public APIs and experiment schemas are versioned before stable release.

## Roles

- **Maintainers** merge changes, publish releases, and protect safety boundaries.
- **Reviewers** evaluate engineering, numerical, UX, accessibility, and documentation quality.
- **Contributors** may propose code, tests, scenarios, research references, and translations.
